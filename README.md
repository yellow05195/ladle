# Ladle — the draw

Same price for everyone. Not the same scoop. And the pot is always exact: the house neither wins nor loses on the draw.

(The product was called PULLED until v17; the program, the sdk package `@pulled/sdk` and their paths keep that name until the chain side is renamed.)

Everyone pays into a window counted in slots. When it closes, one external random seed (ORAO VRF) decides how the window's single bonding-curve buy is split among entries. The shares sum exactly to what the curve sold, at the base unit. Then "sell back now", at curve price, zero fee. Delivered as an embeddable component first, a site second.

All names live in `config/brand.ts`. Code and UI in English only. Brand kit (the Ladle mark and wordmark, X avatars and banner) in `app/public/brand`, generated by `app/scripts/make-brand.mjs`, shown with downloads on `/brand`.

## Read this first

**`docs/RISKS.md` §0 is unresolved.** A wager, a random outcome and a variable reward is close to gambling in most jurisdictions; the on-chain, admin-less, conserved-sum design moves that question, it does not answer it. No legal opinion is written yet. Nothing here is to be deployed on mainnet until it is.

## Status of the seven gates (2026-10-23, details in `/research`)

| gate | verdict | one line |
|---|---|---|
| G1 prior art | **PASS** | no live product draws fill size at a fixed price with a conserved sum (46 queries, links in `research/G1.md`) |
| G2 randomness | **PASS with a design change** | ORAO VRF; Switchboard randomness deprecated Sept 2026. Measured on mainnet (n=314): median 4 s, p90 72 s, p99 113 s. A sequential 20 s loop is **not** tenable; windows are pipelined on a 92-slot grid and settle in order; timeout 900 slots |
| G3 fairness | **PASS after redesign** | the brief's multiplicative law is unfair by 7–265 % per decile and was rejected; the shipped linear law is exact in expectation for every stake size, measured over 10,000,000 windows |
| G4 concentration | **PASS** | per-entry cap 20 % of the window at entry time: the biggest entry explains ≤ 3.6 % of a small player's variance when the cap binds |
| G5 accounting | **PASS on the reference law** | 10,000 adversarial windows, every invariant at the base unit; on-chain execution not run here |
| G6 slot time | **PASS** | 1 slot ≈ 217 ms (measured 2026-10-10..23); 92 slots ≈ 20 s |
| G7 the loop | **UNVERIFIED** | no public source measures re-entry after a losing draw; the "20.5×" figure is a single undefined quote; our own testnet measurement is specified and **not done** |

## Deviations from the brief, on purpose

- **Law**: linear multiplier instead of multiplicative weights (G3).
- **Rounding**: cumulative quota rounding instead of largest remainder — same ±1 bound, paginable in O(1) state (`research/G5.md` §3).
- **Cadence**: pipelined windows instead of a sequential 20 s loop (G2).
- **Curve**: initial virtual token reserve equals the real supply, so the curve can never sell tokens the vault does not hold (`programs/ladle/README.md`).
- **VRF seed**: derived from the sealed window state (entries commitment), not the bare window key, so the oracle cannot precompute a window before it closes.
